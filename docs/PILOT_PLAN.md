# 真楼试点方案（GCCM-BE 实测验证）

> 目标：把"仿真省电 13~18%"变成"实测省电 X%"，获得 IPMVP 口径的可核验数据。
> 前提：已具备完整控制引擎（38 测试全绿）、REST API、配置化、演示图表。

---

## 1. 目标与验收标准

| 验收项 | 标准 |
|---|---|
| **实测省电** | GCCM 控制期 vs 基线期，**省电 ≥ 8%**（空调电费口径），违温 ≤ 2% |
| **数据可核验** | 24h×N 天的逐 5 分钟数据（温度/功率/电价/控制指令），导出 CSV |
| **M&V 口径** | 按 IPMVP **Option B（隔离改造计量）**：同房间/同设备，交替期对比 + 天气归一化 |
| **安全零事故** | 试点期间室温从未超过安全上界（默认 29°C），有手动优先开关 |

**"实测数字"是唯一能改变项目量级的产出**——竞赛文本、DeepSeek 简历、EMC 谈判全靠它。

## 2. 试点对象选择（按可行性排序）

| 候选 | 可行性 | 说明 |
|---|---|---|
| **① 学校宿舍/办公室分体空调** | ⭐⭐⭐⭐⭐ | 自己或朋友可控，业主=同学/自己，决策成本最低；**推荐首选** |

- 空调**独立计量**（分体空调=单独智能插座即可；中央空调需房间计量表）

- 试点期 **≥ 14 天**（至少包含 3 个高温日 + 3 个工作日峰时）
- 房间热负荷**可预测**（办公/机房优于宿舍的随机进出）

## 4. 系统架构与数据流

```text
┌─────────────┐  温度/湿度    ┌──────────────┐
│ 温湿度传感器  │ ───────────▶ │              │
└─────────────┘               │  Home Assistant │
┌─────────────┐  电量/功率    │  (边缘主机)    │  ┌──────────────┐
│ 智能插座      │ ───────────▶ │              │──▶│ GCCMEngine   │
└─────────────┘               │  采集+下发    │  │ (滚动 MPC)   │
┌─────────────┐  红外设定温度 ┌──────────────┘  └──────┬───────┘
│ 万能遥控器    │ ◀─────────── │ 控制指令                 │
└─────────────┘               └───────────────────────┘
```

**闭环（每 15 分钟一个周期）：**
1. 读室温 `T_air`、室外温度 `T_out`（本地气象 API）、电价（分时电价表）
2. `GCCMEngine.optimize(state, time_h, ...)` → 输出制冷功率 `u`（kW，≤0）
3. 将 `u` 映射为**空调设定温度**（见 §5.3），经万能遥控器下发
4. 记录 `(时间, T_air, u, 设定温度, 功率, 电价)` 到 CSV

## 5. 实验协议（M&V）

### 5.1 总体设计：同一房间，交替期对比（ABAB）

| 期 | 时长 | 控制方式 |
|---|---|---|
| 基线期 A1 | 5~7 天 | 原控制（恒温器/原设定，记录现状） |
| 干预期 B1 | 5~7 天 | GCCM 控制 |
| 基线期 A2 | 3~5 天 | 恢复原控制（验证无漂移） |
| 干预期 B2 | 3~5 天 | GCCM 控制（重复验证） |

**总时长 2~4 周。** ABAB 设计能排除"空调老化/季节漂移"的系统性误差。

### 5.2 天气归一化（关键）

省电对比必须**同天气可比**，采用两种方法之一：
- **配对日法**：挑基线期与干预期**室外温度曲线最接近**的成对日期对比（简单可靠）
- **回归法（IPMVP 推荐）**：对基线期数据拟合 `电量 = f(T_out, 时段)`，用拟合模型预测干预期"若无 GCCM 的电量"，与实测对比

> 归一化公式（回归法）：
> `E_day = a·(HDD/CDD) + b·peak_hours + c`，用基线期拟合 a/b/c。

### 5.3 控制映射：GCCM 功率 → 空调设定温度

GCCM 输出制冷功率 `u`（kW），分体空调不是连续可调的，做如下映射：

```text
设定温度 = SETPOINT_BASE - K·u/|u_max|·(上限-下限)
规则：u=0（不制冷）→ 设定 28°C（回差避免短循环）
     u=满制冷   → 设定 22°C
     中间线性插值，且每周期变化 ≤ 1°C（避免压缩机频繁启停）
```

> 若用通断方案：`开/关 = u < -ε`，最小开关周期 10 分钟保护压缩机。

### 5.4 指标口径（与仿真一致，方便对照）

| 指标 | 定义 |
|---|---|
| 空调电费 | `Σ 功率 × 电价 × dt`（分时电价） |
| 违温率 | 室温超出 25~27°C 的时间占比（与仿真舒适带一致） |
| 削峰 | 峰时（11~18h）平均功率下降比例 |
| 节省 | `(基线电费 − GCCM电费) / 基线电费`，天气归一化后 |

## 7. 安全与风险控制（红线）

| 风险 | 防护 |
|---|---|
| **室温失控（最大风险）** | GCCM 安全降级链已就位（求解失败/误差超标自动回退）；再叠加**硬性看门狗**：室温 > 29°C 强制全冷、< 22°C 强制停止 |
| 空调压缩机频繁启停 | 设定温度每周期变化 ≤ 1°C；通断方案最小周期 10 分钟 |
| 数据断流 | 边缘主机每分钟心跳；断流 > 30 分钟电话告警 |
| 业主投诉 | 控制时段避开有人时段；**手动优先开关**（墙插/遥控器随时接管） |
| 天气不热 | 延长基线/干预期各 3~5 天备用窗口；优先选 7~8 月执行 |
